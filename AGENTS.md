## This repo

- Design and decisions live in [PLAN.md](PLAN.md). Work items are GitHub issues; one PR closes one issue.
- Stack: Next.js 16 (App Router, no `src/`), Tailwind v4, shadcn (base-nova), Postgres through `postgres` (postgres.js), bun.
- Schema changes are SQL files in `migrations/` named `NNNN_name.sql`, applied in name order by `scripts/migrate.ts`. Never edit a migration that has been applied; add a new one. The runner wraps each file in a transaction, so a file must not contain its own `BEGIN` or `COMMIT`.
- Decks: `lib/deck/schema.ts` defines the document, and `lib/deck/store.ts` (`mutateDeck`) is the path for saves, agents' edits and renames: the editor's saves against a base version, agents' edits planned while the deck's row is held. Reverts (validated the same way) and deck actions (publish, unpublish, delete, restore) are written by `lib/deck/revisions.ts`. Every query takes the member's `sub`; agents' writes apply at once like the member's, and every change is an entry in the deck's history. Server actions live next to the page that uses them (`app/actions.ts`, `app/decks/[id]/actions.ts`), and each checks the session itself: an action is a public POST endpoint.
- Agents: `lib/mcp/server.ts` holds the MCP tools. Whatever a member can do in the web app needs a tool: `lib/mcp/parity.ts` maps every server action and API route to its tools and its test fails when one is missing; the kinds of edit `editDeckAction` saves (shapes, slides, slide titles and notes, the deck's title) are matched by hand.
- Rendering: `lib/render/svg.ts` (`renderSlideSvg`) is the one renderer for the editor, public pages and MCP snapshots; `lib/render/png.ts` rasterizes with resvg on the server. Text is laid out by `lib/render/text.ts` with Carlito metrics (`carlito-metrics.json`, regenerate with `bun scripts/font-metrics.ts`) and one em per CJK character; never let a renderer wrap on its own. Slide fonts (Carlito, Noto Sans TC) come from `sh scripts/fetch-fonts.sh` into `fonts/slide/` (pinned, sha256-checked); run it before the tests. A deck carries its slide master (`document.master`: layouts with background, artwork shapes, title and number placeholders), read from a `.pptx` by `lib/pptx/import.ts`; `lib/master/layout.ts` (`layoutOf`) gives a slide its layout. The master file (the `.pptx` without slides, `lib/pptx/master-file.ts`) is what an export starts from: built-ins in `template/` (see its README), imported ones in the `masters` table. `lib/master/builtin.json` is generated from `template/*.pptx` by `bun scripts/masters.ts`; `plain.pptx` from `winlab.pptx` by `bun scripts/template-plain.ts`.
- Tests that need Postgres use `lib/test-db.ts` and run only when `TEST_DATABASE_URL` is set (each gets its own schema, dropped afterwards). CI sets it.
- Checks: `bun run typecheck`, `bun run lint`, `bun run format:check`, `bun run test`. CI also builds the image and smoke-tests `docker compose up` with `scripts/smoke.sh`.
- UI follows the ui.zyx.tw design contract (https://github.com/zyx1121/www.zyx.tw/blob/main/apps/ui/DESIGN.md) through the task-web shell: pages render inside `TaskShell` (`components/task-shell.tsx`, `corners.tsx`, `corner-tip.tsx`, `zyx-mark.tsx`, copied from the task-web starter), with page actions in the top-right corner. The theme's dialogs and menus are frosted glass, unreadable over white slides, so pages over slide content act in place instead (see the home page's deck cards). Only 24/16/14 px text (`text-2xl`, `text-sm`, `text-xs`), weights 400 and 500, theme tokens instead of colors. `components/ui/` is owned by the shadcn CLI; add primitives with `bunx shadcn@latest add`, never edit them.
- GitHub text (issues, PRs, comments, docs) is English. UI copy is Traditional Chinese (zh-Hant).
